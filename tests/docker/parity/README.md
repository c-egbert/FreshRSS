# Container parity and assumption probes

These scripts preserve historical reference measurements and validate base-image and scheduler assumptions. They are not a substitute for the current rootless-image capability and contract tests in the [Docker test guide](../README.md#test-the-rootless-image).

## Frozen application references

From the repository root, create an ignored source context from the recorded commit and build both reference images from that snapshot:

```sh
mkdir -p tests/docker/.parity/source
git archive --format=tar --output=tests/docker/.parity/source.tar b33749fe6c9b0a4fec0ccb210b20202282444bfe
tar -xf tests/docker/.parity/source.tar -C tests/docker/.parity/source
docker build -f tests/docker/.parity/source/Docker/Dockerfile \
  --build-arg SOURCE_COMMIT=b33749fe6c9b0a4fec0ccb210b20202282444bfe \
  --build-arg FRESHRSS_VERSION=b33749fe6c9b \
  -t freshrss:scope-parity-debian tests/docker/.parity/source
docker build -f tests/docker/.parity/source/Docker/Dockerfile-Alpine \
  --build-arg SOURCE_COMMIT=b33749fe6c9b0a4fec0ccb210b20202282444bfe \
  --build-arg FRESHRSS_VERSION=b33749fe6c9b \
  -t freshrss:scope-parity-alpine tests/docker/.parity/source
node tests/docker/parity/baseline.mjs
node tests/docker/parity/inventory.mjs
```

The benchmark performs three disposable SQLite installations per image with one CPU and 256 MiB memory limits. It measures installer readiness, a CLI refresh, and container memory, then cleans up its resources. New reports omit Docker context names, engine endpoints, host kernel details, and local account IDs. Historical report files retain their original filenames and are not regenerated by these commands.

## Dedicated Linux engines

The optional engine probe needs a disposable Ubuntu-compatible Linux environment with separate conventional and rootless Docker daemons. `provision-wsl.sh` configures such a test environment; do not run provisioning on a personal or production installation. The test account defaults to `freshrss-test`; set `FRESHRSS_TEST_USER` to use another account.

```sh
sh tests/docker/parity/provision-wsl.sh
```

For the historical scheduler probe, place the verified `supercronic-linux-amd64` asset and saved Debian base image in `tests/docker/.parity/`. The asset checksum and base image identity are validated against the inventory. Create the current base inventory, then run the engine probe from the repository root in the Linux test environment:

```sh
node tests/docker/parity/inventory.mjs
docker image save -o tests/docker/.parity/base-runtime.tar debian:13-slim
python3 tests/docker/parity/engines.py tests/docker/reports/parity-engines.json
```

The probe checks network DNS and local HTTP, fresh-volume and prepared-bind persistence, selected scheduler expressions, scheduled execution as `33:33`, inherited environment, a read-only root filesystem, dropped capabilities, and graceful scheduler shutdown. It uses UTC and records behavior results without storing daemon paths, engine versions, host UID mappings, kernel details, host timestamps, or raw scheduler logs.

This historical probe covers Supercronic on the selected Debian base; it does not validate the current snooze runner or the complete FreshRSS rootless image. Use the current tests in the main [Docker test guide](../README.md#test-the-rootless-image) for that validation.
